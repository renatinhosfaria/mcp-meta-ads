# Auth0 OAuth 2.1 para o MCP Meta Ads — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permitir que ChatGPT autentique no MCP por OAuth 2.1 via Auth0, preservando a API key Bearer existente para clientes legados.

**Architecture:** O Auth0 será o Authorization Server e o MCP será o resource server. O MCP publicará metadata de protected resource, validará JWT RS256 por JWKS remoto com `jose`, exigirá issuer/audience/scopes configuráveis e manterá a API key como caminho de compatibilidade. A rota de metadata será pública e o Nginx encaminhará esse caminho ao backend.

**Tech Stack:** TypeScript ESM, Express 4, Node 24, `jose`, `node:test` + `tsx`, Nginx e Auth0 OIDC/OAuth 2.1.

**Spec:** `docs/superpowers/specs/2026-11-08-auth0-oauth-design.md`

## Global Constraints

- Nunca remover a autenticação `Authorization: Bearer <API_KEY>` existente.
- Nunca registrar, devolver ou commitar API keys, tokens JWT, client secrets ou valores de `.env`.
- OAuth só é ativado quando `AUTH0_ISSUER` e `AUTH0_AUDIENCE` estão presentes; configuração parcial falha no startup.
- Validar JWT com RS256, issuer, audience, expiração e JWKS remoto; exigir os escopos configurados.
- O `resource` canônico é `PUBLIC_BASE_URL` por padrão e deve ser HTTPS.
- A metadata pública é `GET /.well-known/oauth-protected-resource`; `/health`, webhooks e media mantêm o comportamento público atual.
- O endpoint MCP protegido continua em `/mcp`; uploads continuam atrás do middleware de autenticação.
- Testes devem cobrir API key, JWT OAuth, falhas, escopos, metadata, Nginx snippet e a suíte completa.
- Nenhuma configuração real de Auth0 ou deploy de produção será feita sem os valores do tenant/audience fornecidos pelo Renato.

## Review Focus

1. Bearer que não é API key nem JWT válido deve retornar 401 com `WWW-Authenticate` e nunca 403 ou detalhe do token; teste em Task 1.
2. JWT válido com issuer/audience corretos, mas escopo ausente, deve ser recusado; JWT com `scope` ou `permissions` correspondente deve ser aceito; teste em Task 1.
3. Configuração parcial (`AUTH0_ISSUER` sem `AUTH0_AUDIENCE`, ou vice-versa) deve falhar antes de iniciar o servidor; teste em Task 1.
4. Metadata e challenge devem usar o mesmo `resource` HTTPS e issuer exato, inclusive barra final do Auth0; teste em Task 2.
5. A rota de metadata deve chegar pelo Nginx sem tornar `/webhooks/meta` ou `/media/` protegidos; teste de configuração em Task 2 e smoke test antes do deploy.
